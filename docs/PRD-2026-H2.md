# PRD — GonpunClaw PolicyMap 정책지도 스튜디오

- 문서 버전: 1.0
- 작성일: 2026-08-04
- 상태: 구현 후보 확정용 초안
- 대상 저장소: `hosungseo/gonpunclaw-policymap`
- 관련 문서: [`UPGRADE-PLAN-2026-H2.md`](./UPGRADE-PLAN-2026-H2.md)

## 1. 제품 요약

GonpunClaw PolicyMap은 주소가 포함된 행정 엑셀을 업로드하면 공개 가능한 정책지도를 만드는 서비스다. 이번 버전은 기존의 `정해진 형식의 엑셀을 지도에 표시하는 도구`를 `자료 검수, 근거 관리, 반복 갱신, 공개 승인까지 지원하는 지자체 정책지도 스튜디오`로 확장한다.

제품의 핵심 약속은 다음과 같다.

> GIS를 몰라도 기존 업무 엑셀을 올려 5분 안에 출처와 기준일이 명확한 정책지도를 만들 수 있다.

## 2. 배경과 문제

현재 제품은 업로드, 지오코딩, 공개·관리 링크, 검색·필터, 행정경계, 재업로드, 감사 로그를 지원한다. 그러나 실제 현업 엑셀은 열 순서와 명칭이 제각각이고, 주소 변환 성공 여부만으로는 공개 품질을 보장하기 어렵다. 일회성 지도 발행 이후 자료가 언제 기준인지, 누가 관리하는지, 무엇이 바뀌었는지도 알기 어렵다.

해결할 문제는 네 가지다.

1. 사용자가 제품 템플릿에 맞추느라 원자료를 다시 편집해야 한다.
2. 잘못된 좌표와 공개 부적합 열을 발행 전에 충분히 검수하기 어렵다.
3. 공개 지도에서 출처, 기준일, 갱신 상태가 분명하지 않다.
4. 같은 지도를 반복 갱신하거나 조직 안에서 검토·승인하기 어렵다.

## 3. 목표와 비목표

### 3.1 목표

| ID | 목표 |
| --- | --- |
| G1 | 기존 행정 엑셀을 열 순서 변경 없이 업로드한다. |
| G2 | 주소 오류와 민감정보 위험을 발행 전에 발견·수정한다. |
| G3 | 모든 공개 지도에 출처, 기준일, 마지막 갱신일을 표시한다. |
| G4 | 데이터 교체 시 변경점을 확인하고 이전 버전을 추적한다. |
| G5 | 인구감소지역 등 공통 정책 기준과 현장 데이터를 한 지도에서 본다. |
| G6 | 공개·링크 공개·비공개와 검토 권한을 명확히 구분한다. |

### 3.2 비목표

- 범용 GIS 수준의 도형 편집과 공간분석
- 개인별 실시간 위치 추적
- AI가 좌표나 행정 판단을 최종 확정하는 기능
- 출처가 불명확한 공공데이터의 대량 탑재
- 초기 버전의 기관별 과금과 복잡한 조직 관리

## 4. 사용자

### 4.1 주 사용자

| 사용자 | 상황 | 핵심 요구 |
| --- | --- | --- |
| 지자체 현업 담당자 | 시설·사업·민원 현황 엑셀 보유 | 별도 GIS 교육 없이 지도 작성 |
| 자료 관리자 | 정기적으로 최신 엑셀 수령 | 기존 지도 갱신과 변경점 확인 |
| 부서 검토자 | 대외 공개 전 내용 확인 | 민감정보·출처·누락 검토와 승인 |
| 시민·협업기관 | 공개 링크로 지도 열람 | 모바일 검색, 필터, 출처 확인 |

### 4.2 대표 업무

- 복지시설 분포와 서비스 공백 확인
- 사회적경제기업·전통시장·관광자원 공개
- 인구감소지역의 정주·청년 사업 현황 공유
- 안전점검 대상의 내부 비공개 관리
- 여러 부서 자료를 합친 정책자원 현황판 발행

## 5. 핵심 사용자 여정

1. 사용자가 새 지도를 선택하고 기존 XLSX 또는 CSV를 올린다.
2. 시스템이 열의 역할을 추천하고 민감 가능 열을 표시한다.
3. 사용자가 주소·이름·분류·대표값·공개 추가정보 열을 확정한다.
4. 시스템이 주소를 변환해 `성공`, `검수 필요`, `실패`로 나눈다.
5. 사용자가 의심 좌표와 실패 주소를 수정하거나 제외한다.
6. 사용자가 제목, 설명, 출처, 기준일, 담당 부서, 공개 범위를 입력한다.
7. 공개 전 확인 화면에서 데이터·근거·민감정보 체크를 마친다.
8. 지도 발행 후 공개 링크와 관리 링크를 받는다.
9. 새 자료가 오면 기존 지도에 업로드하고 변경점을 검토해 새 버전으로 공개한다.

## 6. 릴리스 범위

| 릴리스 | 목적 | 포함 기능 |
| --- | --- | --- |
| R1 | 믿고 올릴 수 있는 업로드 | 열 연결, 주소 품질 검수, 메타데이터, 공개 전 확인 |
| R2 | 반복 업무에 쓰는 지도 | 요약 대시보드, 업무 템플릿, 정책 기준 레이어, 버전 비교 |
| R3 | 조직이 함께 쓰는 지도 | 권한·승인, 임베드, 공개 API, 공개 지도 디렉터리 |

R1이 이번 PRD의 필수 구현 범위다. R2와 R3는 데이터 모델과 화면 확장을 막지 않도록 설계하되 별도 릴리스 게이트를 적용한다.

## 7. 정보구조

- `/` — 제품 설명, 샘플, 새 지도 시작
- `/upload` — 파일 업로드와 열 연결
- `/upload/jobs/[jobId]/review` — 주소 품질 검수
- `/upload/jobs/[jobId]/publish` — 메타데이터와 공개 전 확인
- `/m/[slug]` — 공개·링크 공개 지도
- `/manage/[slug]` — 데이터 갱신, 버전, 설정, 내보내기
- `/manage/[slug]/versions` — 버전별 변경점과 복원
- `/staff/reports` — 신고 처리
- `/staff/audit` — 감사 기록

실제 라우트명은 구현 과정에서 조정할 수 있지만 사용자 단계는 합치지 않는다.

## 8. 기능 요구사항

### FR-PM-001 파일 접수와 사전검사 — P0

요구사항:

- XLSX와 CSV를 지원한다.
- 시트가 여러 개면 사용할 시트를 선택하게 한다.
- 헤더, 데이터 행 수, 빈 행, 중복 가능 행, 읽기 실패를 발행 전에 요약한다.
- 파일 크기와 행 수 제한은 서버 설정값으로 관리하고 화면에 제한을 안내한다.
- 원본 파일은 처리 목적과 보관기간을 고지하고 보관기간 후 삭제한다.

수용기준:

- 유효한 파일은 1차 미리보기로 이동한다.
- 손상 파일, 헤더 없는 파일, 제한 초과 파일은 원인과 해결 방법을 보여준다.
- 실패한 파일로 지도나 빈 데이터베이스 레코드가 남지 않는다.

### FR-PM-002 열 연결 마법사 — P0

요구사항:

- 헤더명과 표본 값을 이용해 `주소`, `이름`, `분류`, `대표값`, `추가정보`를 추천한다.
- 사용자가 모든 추천을 수정할 수 있다.
- 주소 열만 필수다.
- 하나의 원본 열은 하나의 핵심 역할에만 연결한다.
- 공개할 추가정보 열을 사용자가 개별 선택한다.
- 대표값 열은 숫자 변환 성공률과 변환 실패 예시를 보여준다.

수용기준:

- A~D 고정 순서가 아닌 파일을 수정 없이 처리한다.
- 확정 전까지 다음 단계로 넘어갈 수 없다.
- 공개 제외 열은 마커의 `extra` 데이터에 저장하지 않는다.

### FR-PM-003 민감정보 검사 — P0

요구사항:

- 전화번호, 이메일, 주민등록번호, 계좌, 개인 상세주소 등 위험한 헤더와 값 패턴을 검사한다.
- 명백한 고위험 정보는 업로드를 차단한다.
- 담당 부서 대표 연락처처럼 허용 가능한 항목은 경고 후 사용자가 공개 여부를 결정한다.
- 검사 결과와 사용자의 확인 행위를 감사 로그에 남긴다.

수용기준:

- 차단 항목이 있으면 지도 발행 API를 호출할 수 없다.
- 경고를 무시한 경우 누가 어떤 경고를 확인했는지 기록한다.
- 로그에는 원문 민감값을 남기지 않는다.

### FR-PM-004 주소 변환과 품질 분류 — P0

요구사항:

- 기존 다중 지오코더 폴백과 캐시를 유지한다.
- 결과를 `성공`, `검수 필요`, `실패`로 분류한다.
- 검수 필요 규칙에는 행정구역 불일치, 낮은 정합도, 중복 좌표, 과도하게 동일한 좌표를 포함한다.
- 원주소, 정규화 주소, 공급자, 결과 좌표, 실패 사유를 제공한다.
- 작업은 브라우저 종료 후에도 재개 가능해야 한다.

수용기준:

- 처리 중 새로고침해도 동일 작업 상태로 복귀한다.
- 각 행은 최종 상태와 사용한 공급자를 가진다.
- 검수 필요 건수가 0이 아니면 사용자가 확인 또는 제외를 해야 발행할 수 있다.

### FR-PM-005 검수 편집기 — P0

요구사항:

- 검수 필요와 실패 행만 필터링한다.
- 주소를 수정해 재변환할 수 있다.
- 좌표를 지도에서 직접 이동하고 `수동 보정`으로 표시할 수 있다.
- 행을 발행 대상에서 제외할 수 있다.
- 실패·제외 행을 CSV로 내보낸다.

수용기준:

- 모든 수정은 원본값과 수정값을 구분해 기록한다.
- 수동 좌표는 자동 캐시에 일반화해 저장하지 않는다.
- 지도 발행 건수와 제외·실패 건수의 합이 입력 유효 행 수와 일치한다.

### FR-PM-006 지도 메타데이터 — P0

필수 필드:

- 제목
- 자료 출처
- 자료 기준일
- 담당 부서 또는 관리 주체

선택 필드:

- 설명, 문의처, 이용조건·라이선스, 갱신주기, 다음 점검일
- 대표값 이름·단위, 분류 이름

수용기준:

- 필수 필드가 없으면 공개 또는 링크 공개로 발행할 수 없다.
- 공개 지도에 기준일과 마지막 갱신일이 항상 표시된다.
- 다음 점검일이 지났으면 관리 화면에 갱신 필요 상태를 표시한다.

### FR-PM-007 공개 전 확인과 공개 범위 — P0

요구사항:

- 데이터 건수, 품질 상태, 공개 열, 메타데이터를 한 화면에서 확인한다.
- 공개 범위는 `공개`, `링크 보유자`, `비공개`로 구분한다.
- R1에서 계정이 없을 경우 관리 토큰으로 비공개 접근을 보호한다.
- 지도 발행 직전 민감정보·출처·기준일 확인 체크를 받는다.

수용기준:

- 공개 지도만 사이트맵과 검색 노출 대상이 된다.
- 링크 보유자 지도는 검색·디렉터리·사이트맵에서 제외된다.
- 비공개 지도는 유효한 관리 권한 없이 마커 데이터를 반환하지 않는다.

### FR-PM-008 공개 지도 탐색 — P0 유지·개선

요구사항:

- 검색, 분류, 값 범위, 지도·표 전환, 행정경계, 링크 복사를 유지한다.
- 메타데이터와 데이터 품질 요약을 표시한다.
- 필터 적용 결과 개수를 지도와 표에서 동일하게 유지한다.
- 모바일에서 검색과 필터에 한 번의 조작으로 접근한다.

수용기준:

- 키보드만으로 검색, 필터, 표의 주요 기능을 사용할 수 있다.
- 빈 결과와 지도 로딩 실패에 명확한 대체 안내가 있다.

### FR-PM-009 요약 대시보드 — P1

- 전체·분류별·행정구역별 개수와 대표값 합계·중앙값을 제공한다.
- 현재 지도 범위와 필터에 따라 수치를 다시 계산한다.
- 대표값이 없는 지도에서는 수치 위젯을 숨긴다.
- 표와 집계를 CSV로 내보낸다.

### FR-PM-010 정책업무 템플릿 — P1

- 복지시설, 생활SOC, 사회적경제기업, 빈집·유휴공간, 안전점검, 관광자원 템플릿을 제공한다.
- 템플릿별 권장 열, 공개 금지 열, 예시 행, 안내문을 포함한다.
- 템플릿은 제품 배포 없이 갱신할 수 있는 데이터 구조로 관리한다.

### FR-PM-011 정책 기준 레이어 — P1

- 인구감소지역·인구감소관심지역을 선택형 기준 레이어로 제공한다.
- 공통 시군구 코드로 업로드 위치와 지역을 연결한다.
- 레이어에는 출처, 기준일, 버전을 표시한다.
- 정책 기준 데이터가 만료·변경되면 자동 또는 운영 점검으로 갱신 필요 상태를 만든다.

### FR-PM-012 데이터 버전과 변경점 — P1

- 데이터 교체 시 이전 버전을 보존한다.
- 위치의 추가, 삭제, 내용 변경, 좌표 변경을 구분한다.
- 관리자는 변경점을 검토한 뒤 새 버전을 공개한다.
- 이전 버전 복원은 새 버전을 생성하는 방식으로 처리한다.

### FR-PM-013 협업과 승인 — P2

- 소유자, 편집자, 검토자 역할을 제공한다.
- 공개 상태 변경은 소유자 또는 검토 승인 권한자만 수행한다.
- 초대, 승인, 공개, 복원 행위를 감사 로그에 남긴다.
- 계정 연동 전까지 관리 토큰 방식과의 마이그레이션 경로를 제공한다.

### FR-PM-014 임베드와 공개 API — P2

- 반응형 iframe 코드와 필터 상태를 포함한 공유 URL을 제공한다.
- 공개 지도만 GeoJSON·JSON 읽기 API를 제공한다.
- API 응답에 출처, 기준일, 갱신일, 이용조건을 포함한다.
- 호출 제한과 캐시 정책을 공개 문서에 명시한다.

## 9. 데이터 요구사항

### 9.1 지도 메타데이터 확장안

`maps`에 다음 개념을 추가한다.

- `visibility`: `public | unlisted | private`
- `source_name`, `source_url`
- `data_as_of`
- `owner_department`, `contact`
- `license`
- `refresh_cycle`, `next_review_at`
- `published_at`, `last_data_update_at`
- `current_version_id`

### 9.2 신규 엔터티

- `map_versions`: 버전 번호, 상태, 생성자, 생성일, 공개일, 변경 요약
- `marker_versions` 또는 버전 스냅샷 저장소
- `column_mappings`: 원본 헤더와 공개 필드 연결
- `review_actions`: 주소 수정, 좌표 이동, 제외, 경고 확인
- `map_members`: 사용자와 역할. R3에서 활성화

정확한 저장 방식은 데이터 규모와 복원 비용을 비교해 결정한다. 버전 기능 전에는 원본 파일 보존기간과 마커 스냅샷 정책을 먼저 정해야 한다.

## 10. 비기능 요구사항

### 성능

- 업로드 미리보기는 일반적인 업무 파일에서 사용자가 대기 상태를 인지할 수 있게 2초 안에 진행 표시를 시작한다.
- 공개 지도는 초기 화면에 필요한 데이터만 먼저 로드한다.
- 대량 마커는 현재 클러스터링을 유지하고 브라우저 메모리 한도를 시험한다.

### 신뢰성

- 업로드 작업은 중복 실행에 안전해야 한다.
- 동일 작업 재시도 시 마커가 중복 생성되지 않아야 한다.
- 공급자 장애 시 폴백 결과와 실패 사유가 보존되어야 한다.

### 접근성

- WCAG 2.2 AA를 목표로 한다.
- 지도 정보는 표 보기로도 제공한다.
- 색상만으로 분류와 상태를 구분하지 않는다.

### 보안·개인정보

- 관리 토큰 원문은 서버에 저장하지 않는다.
- 비공개 지도 응답과 내보내기는 서버에서 권한을 확인한다.
- 로그에 원문 IP와 민감한 셀 값을 저장하지 않는다.
- 업로드 원본의 보관기간과 삭제 작업을 운영 문서에 명시한다.
- 공개 전 민감정보 탐지는 보조 장치이며 최종 책임 범위를 화면에 설명한다.

### 관측 가능성

- 업로드 단계별 성공·실패, 지오코더별 오류율, 처리시간을 수집한다.
- 개인 데이터나 셀 원문 없이 운영 지표를 남긴다.
- 오류 코드와 사용자 안내 문구를 일관된 목록으로 관리한다.

## 13. 핵심 수용 시나리오

### 시나리오 A — 열 순서가 다른 복지시설 엑셀

1. 사용자가 `시설명, 읍면동, 소재지, 시설유형, 정원, 담당자` 순서 파일을 올린다.
2. 시스템은 소재지를 주소, 시설명을 이름, 시설유형을 분류, 정원을 대표값으로 추천한다.
3. 담당자 열은 공개 제외 또는 민감 경고 처리한다.
4. 사용자는 원본 파일을 편집하지 않고 검수 단계로 이동한다.

### 시나리오 B — 잘못 변환된 주소 보정

1. 같은 도로명이 여러 지역에 있어 의심 좌표로 분류된다.
2. 사용자는 원주소와 지도 위치를 보고 주소를 보완한다.
3. 재변환 결과를 확인하고 발행한다.
4. 감사 기록에는 원본 주소의 해시 또는 행 식별자와 수정 행위만 남는다.

### 시나리오 C — 공개 자료 갱신

1. 관리자가 새 분기 엑셀을 기존 지도에 올린다.
2. 시스템이 추가·삭제·수정 위치를 요약한다.
3. 관리자가 변경점을 검토하고 새 버전을 공개한다.
4. 공개 URL은 유지되고 기준일과 갱신일만 새 버전으로 바뀐다.

### 시나리오 D — 비공개 안전점검 지도

1. 사용자가 비공개 범위를 선택한다.
2. 공개 링크로 접근하면 데이터가 반환되지 않는다.
3. 유효한 관리 권한이 있는 사용자만 지도와 내보내기를 사용한다.

1. R1에서 비공개 지도를 관리 토큰만으로 제공할지, 최소 로그인부터 도입할지
2. 업로드 원본 파일의 기본 보관기간
3. 좌표 수동 보정 UI를 R1 필수로 둘지 주소 수정 재시도까지만 제공할지
4. 버전을 전체 스냅샷으로 저장할지 변경분 중심으로 저장할지
5. 공개 지도 디렉터리의 등록 기준과 운영 책임자

## 17. 완료 정의

R1은 사용자가 임의 열 순서의 실제 업무 엑셀을 올리고, 공개할 열을 선택하고, 주소 오류를 검수하고, 출처와 기준일을 입력해 안전한 공개 범위로 발행한 뒤 같은 URL에서 갱신할 수 있을 때 완료로 본다.
